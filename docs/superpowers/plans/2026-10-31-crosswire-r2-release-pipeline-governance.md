# R2 Release Pipeline and Governance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tag push builds, attests and publishes the `crosswire` binary for the three tier-1 targets with one command, and the repo carries the governance documents required before the first public tag; proven by `v0.1.0-rc.1`.

**Architecture:** release-plz owns versions, changelog and the `vX.Y.Z` tag (one workspace version, one changelog, one tag from the `crosswire-server` package). cargo-dist owns the generated `release.yml` that builds on the tag, attaches GitHub build-provenance attestations and publishes the GitHub release with a shell installer that `cargo binstall` consumes. A pre-build gate job re-runs the UI drift check so a release can never ship a bundle that differs from source. Governance lands as plain Markdown plus an ADR that reconciles the committed bundle with §11.7.

**Tech Stack:** cargo-dist (`dist`), release-plz, GitHub Actions (SHA-pinned), `actions/attest-build-provenance`, cargo-binstall metadata, Dependabot.

**Spec:** `docs/superpowers/specs/2026-10-31-crosswire-r2-release-pipeline-governance-design.md`

## Global Constraints

- No new Rust dependencies; `Cargo.lock` changes only for the version bump of workspace crates.
- `unsafe_code = "forbid"`, MSRV 1.88, `cargo build` Node-free, `cargo deny check` clean.
- Every GitHub Action pinned by full commit SHA with a `# vX.Y.Z` comment.
- Conventional Commits, ≤72-char subject, real body, NO AI attribution trailer (verify `git log -1 --format=%B | grep -ci claude` == 0).
- Full CI gate before push: `just lint`, `just doc`, `cargo deny check`, `cargo test --workspace` (once, background, in Task 3), UI lint/test/`ui-dist-check`.
- Generated files (`release.yml`, `dist-workspace.toml` sections dist owns) are never hand-edited beyond what the spec names; `dist generate --check` guards drift in CI.

## Review Focus

1. A tag whose version differs from `[workspace.package] version` → dist refuses the release; the plan pins `0.1.0-rc.1` on the branch (Task 0) and the controller tags exactly `v0.1.0-rc.1`.
2. `release-plz` PR opened with `GITHUB_TOKEN` never triggers `ci.yml`, so a release PR would merge untested → workflow requires `RELEASE_PLZ_TOKEN` and fails fast when absent (Task 0 test: workflow step asserts the secret).
3. A release built from a bundle that drifted from `ui/` → the pre-build gate job runs `just ui-dist-check` and the build jobs `needs` it (Task 1).
4. `npm ci --ignore-scripts` breaking a UI dependency that needs an install script → `just ui-dist-check` must still pass after the flag change (Task 1 step).
5. `cargo binstall` falling back to a source build because `pkg-url` does not match dist's artifact name → Task 3 verifies the rc.1 asset names against the binstall template by downloading with the rendered URL.
